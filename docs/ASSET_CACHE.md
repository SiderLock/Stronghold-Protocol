# 素材预缓存

预缓存把已校验的游戏素材保存到玩家浏览器。优先使用服主分发的完整 ZIP 素材包，在线功能可在用户明确操作后获取目录并补齐缺失或更新的文件。导入在玩家设备上完成，素材包和解压内容不会上传游戏服务器。**目录不会在初始化、检查、准入或失败重试时自动下载**；没有本地目录的冷浏览器也可以在面板中明确点击「在线获取完整目录（限速）」或「在线补齐缺项（限速）」，先取得当前目录，再继续下载全部缺项。已有目录与实际缓存、目录版本落后者可显式点击「手动更新目录（限速）」。

完整预缓存需要 **HTTPS 或 localhost**，以及支持 Service Worker、CacheStorage、Web Crypto、Worker 和 Web Locks 的现代浏览器。默认允许未完整预缓存，普通 HTTP/IP 或不支持这些能力的浏览器仍可按原方式游玩；服主开启严格准入后，四种新进入操作需要完整预缓存。内网穿透是否支持预缓存取决于玩家最终访问的地址是否为 HTTPS。

## 玩家使用

大厅和房间提供「预缓存」入口；大厅按钮在导航栏左侧，以绿色背景强调。输入代号的标题页不提供此入口。准备素材时停留在大厅或房间待机页，本地完整包导入为强烈推荐方式。

1. 从服主提供的渠道下载完整 ZIP 素材包，保留 ZIP，不必自行解压。
2. 点击「导入本地素材包」，选择下载的 ZIP。浏览器先核对包内目录的 SHA-256 与服务器小型版本摘要，再逐文件核对大小和 SHA-256，通过后才写入缓存。包内目录须匹配当前服务器；已有旧目录者先按第 4 步更新目录，原素材仍可按 SHA 复用。
3. 查看已缓存数量和仍需补齐数量。有缺项时可以再次导入同一包、其他适用包，或点击「在线补齐缺项（限速）」。没有本地目录或目录已过期时，这个按钮会先显式获取当前完整目录，再下载缺项；完整、未变化的文件会复用。
4. 更新后点击「检查更新与缺项」；若提示目录不符，导入当前完整包、包含当前完整目录的新增量包，单独导入当前目录 JSON，或在已有目录 / 缓存时点击「手动更新目录（限速）」。没有目录，或旧目录的素材已被清空时，可点击「在线获取完整目录（限速）」。文件是否需要更新按内容判断，不因发布版本号变化而重下全部素材。

**单独导入目录不会安装素材，也不等于完成预缓存。** 它只说明当前需要哪些文件；数量来自本地实际缓存扫描。目录保存在本站 Cache Storage，刷新后复用；反复打开面板不请求完整目录，也不反复请求小摘要。显式检查、导入、补齐与准入前会重新校验小摘要，避免拿旧目录补齐新服务器。

面板常驻显示本地目录是否已导入、是否匹配服务器，以及本地与服务器的完整内容版本（SHA-256）。版本是素材清单内容的哈希，不是游戏发布版本号；目录已匹配也不代表素材全部缓存。版本文字可选择复制，长哈希自动换行。清理素材缓存后目录仍保留，显示与实际素材进度分别更新；旧目录且素材为空时，仍可在线取得当前目录并补齐。

不完整或旧版 ZIP 中仍与当前服务器一致的素材可以复用，未匹配、已变化或校验失败的文件不会冒充有效缓存。不是当前素材清单的额外文件会跳过；带有不安全路径、重复条目或加密文件等异常结构的包会拒绝。原版游戏安装包不是本功能的素材包。

**支持多个包累积导入。** 先取得当前目录，再导入旧完整包和适用的增量 ZIP；已有旧素材可按内容哈希复用。当前标准 CLI 生成的完整包、增量包和独立 JSON 都携带同一份当前完整目录：首次导入新增量可取得目录，但仍缺基础素材。历史增量包若只带部分目录，仍需先导入当前 JSON 或完整包。每次导入保留已有有效文件，重复导入会复用；当前版本的有效缓存不会被旧包内容覆盖。无需先解压或在磁盘上合并 ZIP，也不要在两次导入之间清理缓存。

增量包只包含某个基线之后新增或变化的素材，首次使用时单独导入它仍会缺少旧素材。打开已更新的站点，点击「检查更新与缺项」后再导入；若服务器还运行旧版本，新素材可能被视为额外文件跳过，更新站点后需要重新导入增量包。最后以「仍需补齐 0」为完成依据。

操作可以暂停；关闭弹窗会继续当前任务，关闭页面则停止任务并保留已写入的文件。再次打开后检查缓存，再选择导入或补齐即可接续。接续以**完整文件**为单位，正在处理的单个文件可能需要重新处理。

进入对局会停止批量导入、补齐、目录更新和完整校验，返回大厅后手动继续。同站点另一标签页处于对局时也会阻止修改操作；同一浏览器同站点同时只允许一个页面进行导入、下载、目录更新、深度校验或清理，其他页面会收到忙碌提示。普通游戏素材请求保持原来的加载方式，不会排在批量下载后面。

## 检查、存储与清理

| 操作或状态 | 含义 |
|---|---|
| 导入目录 JSON | 导入本地完整目录，验证目录摘要并与服务器小摘要匹配，然后扫描已有素材；目录本身不代表素材已齐 |
| 在线获取完整目录（限速） | 仅用户明确点击时获取当前完整目录；可用于冷浏览器或清空素材的旧目录，获取后仍需点击补齐或继续当前补齐任务；失败、取消或目录校验不通过不写入目录 |
| 手动更新目录（限速） | 已有目录、实际有缓存且版本不匹配时可用；更新后只扫描复用，不自动补齐；失败、取消或目录校验不通过保留旧内容 |
| 检查更新与缺项 | 读取服务器小型版本摘要，对照已导入目录及浏览器实际缓存条目；不自动获取完整目录，不重新读取所有素材计算哈希 |
| 完整校验 | 在本机逐文件重新读取内容、核对大小和 SHA-256；发现损坏后移除对应缓存并显示缺项，不重新下载全部文件 |
| 申请持久保存 | 向浏览器申请保护本站数据，免于因空间压力自动清理；浏览器可能拒绝，界面显示实际结果 |
| 清理素材缓存 | 删除本功能的素材缓存；保留目录、玩家身份、设置和本机战绩。清理后可重新导入或显式在线补齐 |
| 服务器素材存在缺项 | 服务器只能提供当前实际可用的文件；客户端不能补出服务器没有的内容，应由服主补齐后重启 |

持久保存被允许后，浏览器会保护本站数据免于因空间压力被自动清理。申请通常不会弹出提示，浏览器会直接决定是否授予；窗口显示处理中、已允许、未授予、不支持或申请失败。未授予时现有缓存仍可使用，并可在以后重试；已允许或不支持此 API 时按钮禁用。主动清理站点数据仍会删除缓存。

素材保存在浏览器配置目录中的 **CacheStorage 站点数据**，由浏览器管理，没有需要玩家手动放置文件的安装目录。素材按内容哈希复用，关闭浏览器或重启设备后通常仍可使用，不需要保持解码后的图片常驻内存。

缓存按「协议＋域名＋端口」和浏览器配置隔离。更换域名、端口、浏览器、用户配置或设备后需要重新导入；同一份 ZIP 可以重复使用。无痕模式、浏览器清理、扩展或系统存储管理也可能删除缓存，申请持久保存不等于永久保留。游戏中的「清理素材缓存」与浏览器的「清理站点数据」不同，后者还可能删除身份、设置和本机战绩。

界面的本站用量和配额来自浏览器估算，不等于设备全部可用磁盘。需要留出素材、浏览器索引和更新期间旧内容保留的空间。空间不足时保留已完成文件，释放空间后再继续；不要只根据 ZIP 压缩大小判断所需容量。

唯一的合并 Service Worker `/asset-cache-sw.js`（作用域 `/`）接管页面后，已缓存且匹配当前清单的素材直接从本机返回，音频的 `/media/` 地址与原素材地址共用缓存；标题页「导入素材包」写入的素材也由同一个 worker 命中，不再需要第二个 worker。旧经典 `/sw.js` 没有持久对局 pin，页面另用 20 秒 localStorage 播放租约（5 秒心跳、pagehide 释放）在迁移升级前保护其他标签的对局。未命中时仍从服务器加载，符合清单且完整的响应可按需加入缓存。网页、应用代码、游戏数据、公告及 WebSocket 通信不属于此素材缓存，预缓存不是离线游戏功能，也不消除联机通信。页面首次接管前的请求及普通浏览器缓存仍遵循现有规则。

部署后，新页面可能暂时仍由旧版缓存组件控制。显式目录更新、导入、补齐或完整校验会先检测组件协议；只有同站点全部标签页均未进行对局时，才激活等待中的新组件，保留各页面固定目录和已有素材，再执行操作。普通初始化、检查和清理不强制激活。升级不可用时面板显示组件升级提示，可关闭本站全部游戏标签页后重新打开；无需清空素材。旧目录更新同 IP 冷却为 **5 秒**，仅服务器实际返回 429 时显示 `Retry-After` 倒计时；下载、校验或组件错误会显示自身原因，不再统一等待 30 秒，且不会自动重试。

## 服主制作与分发完整包

先安装当前版本需要的素材、字体及可选本地提取素材，并核对 `data/assets.json`、`data/local-assets.json`。召唤物补充素材位于 `public/assets/local/spine/token/`，对应清单必须随素材同步。打包工具还会跟踪 Spine 图集贴图及棋盘运行时依赖，完整包不会仅凭目录总大小判断是否完整。

在项目根目录执行：

```bash
# 只检查清单、文件与逐文件 SHA-256，不生成 ZIP
npm run assets:pack -- --dry-run

# 生成完整包
npm run assets:pack

# 只导出完整目录 JSON，沿用现有大包，无需重新压缩素材
npm run assets:pack -- --catalog-only

# 新增量包：从旧完整目录比较，内置当前完整目录，仅装变化的素材内容
npm run assets:pack -- --delta --base-catalog ./old-catalog.json

# 只核对增量计划，不生成文件
npm run assets:pack -- --delta --base-catalog ./old-catalog.json --dry-run

# 可选：指定输出目录
npm run assets:pack -- --out ./runtime/asset-pack-distribution
```

默认输出为 `.cache/asset-cache-pack/Stronghold-Protocol-assets-<内容版本前12位>.zip`。工具使用 Node.js 逐文件压缩，不依赖 Bandizip；可以用常规解压工具查看生成的 ZIP。包内只有素材及 `manifest.json`，没有服务器程序、依赖、身份或私人公告。存在必需缺项、校验失败或同名成品包时拒绝生成或覆盖；安装新素材后内容版本改变，会产生新文件名。生成物和游戏素材不提交 Git。

`--catalog-only` 输出 `.cache/asset-cache-pack/Stronghold-Protocol-catalog-<内容版本前12位>.json`，内容与同版本完整 / 新增量 ZIP 的 `manifest.json` 完全一致；也可从包内提取该文件分发。目录 JSON 仍推荐从外部渠道随完整包分发，但玩家也可在面板中明确请求服务器提供当前完整目录。服务器只在用户操作时发送目录，并与在线补齐共用限速和紧急保护；旧素材 + 当前完整目录 + 对应增量 ZIP 可以组成完整缓存。

**2026-10-09 本次完整包实际结果：**12,249 个素材文件，原始总量 **611.77 MiB**，ZIP **477.11 MiB**。包含新补入的 39 套召唤物、117 个文件，中文/日语语音、字体和当前本地补充素材。数字只描述此次实际部署素材，后续以打包结果和服务器清单为准；浏览器因内容去重或存储开销，实际占用可能与原始总量不同。

**2026-10-10 v0.2.3 更新：**完整素材版本 `dd40447a61c1`，12,562 个文件、原始 **618.07 MiB**，完整 ZIP **481.97 MiB**。相对于此前 `c746f84563a3` 完整包（本地名「素材包c746f84563a3.zip」），新增 **313** 个文件，无原文件变化或删除；增量 ZIP **4.87 MiB**。成品命名为 `Stronghold-Protocol-assets-dd40447a61c1.zip` 和 `Stronghold-Protocol-assets-delta-c746f84563a3-to-dd40447a61c1.zip`；详见 [打包与验证记录](development/records/2026-10-10-08-assets-v023-pack.md)。

上述历史增量通过独立脚本生成，包内只带部分目录，保持原样。自 [DEV-20261011-02](development/records/2026-10-11-02-manual-catalog-update.md) 起，正式 CLI 支持 `--delta --base-catalog OLD.json`：基线须为合法旧完整目录，ZIP 始终写入最新完整 `manifest.json`，仅装基线未包含的 SHA / 大小内容，同内容去重。删除、重命名或仅别名变化可生成只含目录的增量；同版本拒绝生成。文件名为 `Stronghold-Protocol-assets-delta-<旧版本前12位>-to-<新版本前12位>.zip`。完整目录不代表增量 ZIP 含全部素材，首次使用仍需要基础内容；增量只对应指定基线，不能当通用完整包。

将 ZIP 提供给玩家后，由玩家下载并本地导入。可以使用服主自己的静态下载站或外部网盘分发，避免游戏服务器承担首次整包流量。本功能不自动上传网盘，不依赖网盘 API，也不要求玩家向游戏服务器上传 ZIP。更换分发渠道不影响已经导入的内容。

服务器缓存清单按当前素材计算并在进程内固定。更新素材与相关清单后应重启服务器，并在更新后的素材目录制作新包；部署重启会结束正在运行的对局，参见 [部署指南](DEPLOY.md)。下载检测到清单与磁盘不一致会失败，不会以旧哈希提供新文件。玩家重新检查后只补变化文件，已打开页面使用的旧素材版本会被保留，避免对局中途混用图集与贴图。

## 服主要求完整预缓存

服主可执行 `node tools/server-settings.mjs asset-cache required`，动态限制新创建、加入、最快匹配和观战；`asset-cache optional` 恢复默认允许。命令保存在本机私有配置，不开放网页管理接口，也不改变已有对局断线续玩。配置目录、启动默认值、旧配置兼容及数量报告边界见 [服主运行配置](SERVER_SETTINGS.md#完整预缓存准入)。

客户端在进入前请求小摘要并重扫实际缓存键；只有当前目录、服务器素材完整、所有文件与总字节数齐全，正常客户端才满足要求。目录 JSON 自身不会使玩家获得准入；浏览器清理缓存后会重新拒绝。旧素材可按 SHA 复用，补齐到服务器当前内容版本即可。准入字段通过紧凑 v1 的既有扩展位传输，已发布的位置表保持不变。

`readyFiles` 按目录中的文件条目计数，`readyBytes` 累加这些条目的原始字节数：只有对应 SHA 缓存键实际存在才计入。相同内容可共用一个物理缓存键，但每个目录条目分别计入逻辑数量与字节数；音频别名不另计文件。它们与服务器的 `totalFiles` / `totalBytes` 对应，与浏览器估算的物理存储占用不同。

默认允许模式下，未导入素材的玩家仍会按实际使用请求普通素材；页面代码、游戏数据和 WebSocket 仍有必要流量。关闭旧目录入口和取消自动目录下载消除重复传输；显式手动更新受同一字节预算保护，其他必要流量仍存在。

## 在线补齐限流

在线补齐、冷启动时显式获取完整目录与显式手动目录更新使用同一个下载限流器。默认不限速；服主可以用 CLI 在运行中设置预算：

| 项目 | 默认值 |
|---|---|
| 单个 Node.js 服务进程的总预算 | **不限** |
| 单客户端网络地址共享上限 | **不限** |
| 同时处理的下载 | 全局至多 24 个，同客户端网络至多 2 个 |
| 分配方式 | 总预算内按活跃客户端公平轮转，同客户端的多个请求共用其上限 |

多人下载时在服主设置的总预算内动态分配；人数减少后其余客户端可使用释放的份额，但不超过各自上限。默认不设总预算和单 IP 预算。家庭、校园等共用公网 IP 的玩家会共享该网络上限。队列满时返回 429 和重试间隔，客户端等待重试；多次重试仍失败时保留进度供稍后继续。

服主可在服务器安装目录执行以下命令，修改会持久保存并由运行中的服务器约 1 秒内读取：

```bash
# 兼容原先的总 8 Mbps / 单 IP 4 Mbps 预算
node tools/server-settings.mjs asset-cache-limit 8 4

# 恢复默认无限制
node tools/server-settings.mjs asset-cache-limit unlimited unlimited

# 查看当前设置
node tools/server-settings.mjs show
```

命令参数单位是 Mbps；环境变量仍使用字节/秒。将总预算设为 `0` 会关闭在线目录和素材补齐，仍可导入本地 ZIP / JSON。该限速只约束在线目录与素材补齐，不排队普通游戏请求。

两个不同公网 IP 同时补齐时，各自速度取决于服主设置的单 IP 与总预算；默认不受此限速器限制。若启动环境显式设置过旧值，仍会作为启动默认值生效；可用上述 CLI 写入持久配置覆盖它。

此限流器不测量云服务器实际剩余出口、不按标称峰值自动提速。另有下述带宽紧急保护根据实际出口与通信拥堵识别持续异常；它不代表取得了云厂商的实时容量。普通游戏 HTTP、公告和 WebSocket 不使用补齐字节预算；首次按需加载仍会消耗流量。因此完整包外部分发和本地导入优先，不建议让所有玩家用在线补齐下载空缓存的全部素材。

使用以下环境变量，单位均为**字节每秒**，不是 Mbps 或 MiB/s；设置后重启服务生效：

```powershell
# Windows PowerShell：按字节/秒设置启动默认值（持久 CLI 设置优先）
$env:SP_ASSET_CACHE_TOTAL_BPS = '1000000'
$env:SP_ASSET_CACHE_CLIENT_BPS = '500000'
npm start

# 完全关闭在线补齐；本地 ZIP 导入仍可使用
$env:SP_ASSET_CACHE_TOTAL_BPS = '0'
```

```bash
# Linux/macOS
SP_ASSET_CACHE_TOTAL_BPS=1000000 SP_ASSET_CACHE_CLIENT_BPS=500000 npm start
```

多个 Node.js 进程或多台服务器各有独立预算，不会自动共享全服令牌。采用多实例部署时，应按实例分摊预算，或在统一入口额外设置限流。

## 带宽紧急保护

Linux 服务默认每秒读取 `/proc/net/dev` 的实际出口，自动从 `/proc/net/route` 选择默认出口网卡；也可以显式指定 `eth0`、`ens5` 等网卡。先取得 5 秒测量窗口，再要求异常持续 15 秒，默认最早约 20 秒触发；这是一项保守的应用拥堵判断，不能独立证明阿里云的实时限额。

补齐仍有至少 64 KiB 待发内容时，期望速度按当前服主预算和有需求的客户端计算；默认不限速时不使用固定带宽值作为判定基线。实际出口低于期望的 60%，并有至少两个独立网络的下载写入背压，才判定持续异常；单个慢下载者还须有正在对局的 WebSocket 队列或心跳延迟佐证。同 IPv6 `/64` 不算两个独立网络。磁盘准备、无需求、短暂慢速和需求空档不会连续累计。连续更换的小文件同样参与判断，不要求一个大文件保持下载。

取消补齐后，至少两个独立网络、且不少于当前对局网络半数持续拥堵或心跳延迟，实际出口低于默认 `500000 × 60% B/s` 时也能触发保护。这条规则防止恢复后没有补齐需求、却仍有多人通信受阻的情况；不会因一个慢网玩家单独冻结全服。

保护开启后：

- 立即销毁所有补齐/目录更新响应及准备中的下载 lease。普通 HTTP 响应和已写入 TCP 的普通连接也关闭，已升级的 WebSocket 保留。素材（`/assets/`、`/fonts/`、`/media/`）、补齐接口和其它大流量请求得到小型 `503`、`Retry-After` 与关闭连接提示。页面壳与运行时代码（`/`、`/js/`、`/css/`、`/vendor/`、`/shared/`、`/sim/`、`/data/`、`/data.js`）以及 `/healthz` 保留，已打开或刷新的对局仍能加载渲染器（`server/http/routes.js` `isEmergencyShellPath`）。
- 停止大厅目录广播，拒绝新身份、新建、加入、最快匹配、观战、开局和局内聊天等额外操作。现有等待房连接保留；正在进行的对局原成员及原观战者凭有效令牌可重连，冻结期间不会消耗对局续连窗口。同房同角色重同步、查看和主动退出保留。
- 所有 Match 阶段 timer/interval、AI 服务端模拟、领袖与联防时钟冻结。推进意图和战斗报告暂时拒绝；断线/离开的玩法后果延迟到恢复，用户主动放弃最后一个真人席位仍会结束对局。恢复按剩余时间重建 timer，平移 deadline 和战场时钟，不补跑冻结时间。
- 已打开的新客户端收到小型 `m.emergency` 后显示持久提示，停止本地模拟/报告和倒计时，取消补齐。welcome 与 `m.public` 重复携带状态。恢复后结果重发，补齐必须玩家手动继续，避免所有下载一起自动重开。

按用户确认，每 **60 秒尝试恢复**。如果当时仍有对局队列/心跳拥堵，或任一正在进行的对局没有真人在线，则保持冻结并再等 60 秒；具备条件后开放网站并继续对局。恢复是试恢复，不是测得云容量正常；继续异常会再次触发。仅看空闲网卡无法确认带宽已经恢复。

以下为启动配置，修改后重启服务；自动检测默认关闭，不设置即可保持关闭：

| 环境变量 | 默认 | 含义 |
|---|---|---|
| `SP_BANDWIDTH_EMERGENCY_ENABLED` | `0` | `1` 开启自动检测；关闭时不读取网卡、缓存需求或对局拥堵，也不建立检测定时器 |
| `SP_BANDWIDTH_INTERFACE` | 空 | 自动选择默认 IPv4 出口；显式设置时直接读取该网卡 |
| `SP_BANDWIDTH_POLL_MS` | `1000` | 采样间隔；`0` 仅供程序化手动采样，不自动定时 |
| `SP_BANDWIDTH_WINDOW_MS` | `5000` | 出口速率平均窗口 |
| `SP_BANDWIDTH_TRIGGER_MS` | `15000` | 持续异常时间 |
| `SP_BANDWIDTH_RATIO` | `0.6` | 实际出口与期望预算的低速比例 |
| `SP_BANDWIDTH_MIN_CLIENTS` | `2` | 下载多网络佐证下限，最少 2 |
| `SP_BANDWIDTH_MIN_PENDING_BYTES` | `65536` | 下载需求的待发送字节门槛 |
| `SP_BANDWIDTH_GAME_BPS` | `500000` | 无下载时的通信拥堵判定基准，B/s；不限制游戏发送速度 |
| `SP_BANDWIDTH_AUTO_RESUME_MS` | `60000` | 尝试恢复间隔；`0` 不自动恢复，仅供程序化管理 |

```bash
# 服主命令开关（写入 runtime/server-settings.json，运行中约 1 秒生效）
node tools/server-settings.mjs bandwidth-emergency on
node tools/server-settings.mjs bandwidth-emergency off

# 可选：启动时开启，并明确使用观察流量时的 eth0 网卡
SP_BANDWIDTH_EMERGENCY_ENABLED=1 SP_BANDWIDTH_INTERFACE=eth0 npm start

# 当前状态、真实网卡采样和触发依据
curl -s http://127.0.0.1:3000/healthz
```

`/healthz.bandwidthEmergency` 包含 `active`、`retryAt`、配置、下载需求、实际 `detection.txBps`（B/s）、网卡、背压与触发规则。`lastTrigger` 保留最近触发时的速度、期望预算、异常时长、下载与对局拥堵计数，恢复后仍保留至下次触发；不含 IP 或玩家身份。Windows、读不到 `/proc` 或无默认网卡时自动检测不可用，不从应用写入字节伪造网卡速度；状态会显示 `supported` / `available`，IPv6-only 路由需显式指定网卡。检测配置非法会拒绝启动。

服主 CLI 的 `bandwidth-emergency off` 会停止采样、需求/拥堵读取和检测定时器，并释放当前保护状态；再次执行 `on` 才恢复检测。默认关闭可避免普通服务器因为低流量、错误网卡或共享出口而误触发；开启后仍应以 `lastTrigger` 的联合证据校准，不把它当作阿里云容量的直接证明。

服务器应用无法撤回已经发出到链路或反代缓冲里的字节，也无法熔断由 Nginx/其他进程直接提供而未经过 Node 的静态下载。Node 普通响应携带 `X-Accel-Buffering: no`；反代须尊重该头并将游戏资源经 Node 转发。小通知共用原 WebSocket 出口，完全堵塞时无法保证即时到达；服务端冻结不依赖通知成功。保护中的原对局 socket 已超过硬队列上限时停止追加消息，保留连接等待排空及重同步。旧客户端需在新对局前刷新才能识别提示/冻结字段。

实现及验证边界见 [DEV-20261011-07](development/records/2026-10-11-07-bandwidth-emergency.md)、[DEV-20261012-03](development/records/2026-10-12-03-bandwidth-emergency-toggle.md) 与 [D030](development/DECISIONS.md#d030)。本地测试不等于阿里云实际雪崩验证，部署后应观察触发证据和误报情况。

## HTTPS 与反向代理

Service Worker 文件 `/asset-cache-sw.js` 必须通过同一 HTTPS 站点提供，作用域为 `/`；同一作用域只能有一个 worker，因此页面不再注册旧的 `/sw.js`（它只作为不支持模块 worker 的浏览器的经典回退，以及旧页面过渡用）。不要把该文件缓存为永不更新的内容，也不要把补齐接口响应改成下载附件或跳转到其他域名。`/api/asset-cache/catalog` 仅在用户明确操作时返回当前完整目录，受素材限速器和紧急保护约束；初始化、检查、准入和失败重试仍只请求小型 `/status`，不会自动获取完整目录。`/api/asset-cache/status` 只提供版本、总数、总字节数、完整度和下载政策，正文大小不随目录文件数增长。文件补齐提供完整、未压缩的 200 响应，浏览器校验后才保存，不使用 HTTP Range 续传。

### 显式目录更新接口

`GET /api/asset-cache/catalog-update` 用于有实际缓存的旧目录显式更新：须有 `X-Asset-Cache-Update: manual` 请求头，以及且仅有 `from`（旧目录完整 SHA）、`to`（当前小摘要完整 SHA）、`readyFiles` / `readyBytes`（旧目录实际扫描的正整数缓存数量 / 字节数）四个查询参数。目录已匹配不下载；无目录或重扫后实际缓存为空时，显式目录获取 / 补齐改走冷启动 `/api/asset-cache/catalog`。游玩中或管理锁不可用时两条获取路径均拒绝。普通检查、深度校验、初始化、重开和准入不会调用完整目录接口。

服务端拒绝缺少手动标志、无效 / 重复参数、空报告、相同版本和过期目标版本。当前目录更新、冷启动目录获取与文件补齐共享服主可调字节预算（默认不限）、全局 24 / 单 IP 2 并发槽以及在线禁用开关；同 IP 每 5 秒最多开始一次旧目录更新，冷却及并发繁忙返回小型 429 和 `Retry-After`，取消传输保留剩余服务端冷却。目录正文和异步 gzip 在进程内各缓存一次，不为每位玩家重新压缩；无 gzip 能力时仍在同一限流器发送原 JSON。两种响应均 `no-store`、禁止代理缓冲，32 MiB 上限按未压缩正文计算。

客户端仅在显式点击后扫描并发送报告，限制解压后的完整正文大小，验证目录 SHA 和传输结束后最新服务器摘要，重新检查游玩锁后才固定新目录。失败、暂停、跨标签游玩或服务器换版均保留旧目录 / 素材；仅实际 429 启动与 `Retry-After` 对应的倒计时，不强加固定客户端冷却，也不自动重试。目录获取成功只重扫并复用，不自动补齐或清理旧内容；明确点击补齐则取得当前目录后继续下载缺项。完整预缓存准入继续按新目录的真实缺项核验。

缓存数量自报与既有准入一样，是正常客户端的流量约定，服务端不能独立读取远端磁盘。刻意伪造请求不构成磁盘验证证明，但仍受共用字节预算、并发限制和服务端 IP 冷却保护。当前手动策略及维护依据见 [D025](development/DECISIONS.md#d025)、[D038](development/DECISIONS.md#d038)、[目录恢复记录](development/records/2026-10-14-03-asset-catalog-recovery.md)。

补齐响应包含 `X-Accel-Buffering: no`。反向代理应允许流式转发，避免先缓存整份响应再突发发送给玩家。普通 Nginx 直连代理可以在现有 HTTPS `server` 内单独增加：

```nginx
location = /api/asset-cache/file {
    proxy_pass http://127.0.0.1:3000;
    proxy_buffering off;
    gzip off;
    proxy_read_timeout 120s;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $remote_addr;
    proxy_set_header CF-Connecting-IP "";
}
```

这只是补齐接口配置，不替代现有页面和 WebSocket 代理。`TRUST_PROXY=auto` 默认仅接受来自本机或私有网络代理的来源头；普通 Nginx 例子清空未使用的 Cloudflare 来源头，并覆盖玩家提供的来源信息。经过可信 CDN、多层代理或内网穿透时，应按实际链路配置真实 IP，不把未校验的任意请求头当成玩家地址。代理不传真实来源时，多个玩家可能被识别为同一个客户端网络并共享限速。已有 HTTPS 与联机配置参见 [部署指南](DEPLOY.md)。

## 本地目录约定与维护入口

目录仍使用 schema 1。规范内容版本为 `SHA256(UTF8(JSON.stringify({schema:1, files})))`；`files` 顺序及各条目内 `aliases` 顺序固定，条目键顺序为 `url, bytes, sha256, type, aliases`。导入时规范化键顺序，再验证完整摘要；修改 URL、大小、SHA 或别名而保留旧版本会拒绝。应用名称、完整度等元数据不进入内容版本，因此另与服务器摘要核对；服务端缺项不视为完整预缓存。

v0.2.6 的哈希地址作为精确别名加入目录：普通文件使用自身哈希，Spine 的骨骼、图集与纹理页共享模型聚合哈希，音频沿用服务端的扩展优先级。主 URL 和缓存键仍为普通路径与完整 SHA-256；不会全局剥掉请求哈希去匹配旧目录。新增别名会改变目录内容版本，即使所有素材字节都未变化。已有目录与缓存者明确更新目录后便可复用；冷浏览器先取得当前 JSON / 完整目录，再累积导入旧包。旧页面固定的目录和未知哈希仍走各自原有边界，不能借新别名读取其他版本。单条目最多 32 个别名，支持可选场景的 `.bin` 文件。

`shared/assetCache.js` 定义摘要、校验和 Cache Storage 路径；页面从 `sp-asset-cache-meta-v1` 的 `latest` / `catalog/<version>` 恢复目录，兼容已安装的旧 SW。Worker 的 `read-catalog` 在写入任何素材前限长读取 JSON / ZIP 目录；SW 保存每页面 pin，直接重连可恢复初始版本，已固定的对局页不能切换版本。旧页面的完整目录请求会被拒绝，更新后刷新页面即可使用已保存的目录与素材，不需要清理缓存。

0.3.1 的全量目录有 18,372 个文件、18,242 个唯一内容键。Chrome 的 `Cache.keys()` 查询有结果体积上限（"Operation too large"，实测 15,000 条带 header 的内容键就会触发），因此预缓存不再枚举整个 cache：worker 逐条用 `cache.match` 判定已缓存内容，并在操作结束时把已存 SHA 写进 `sp-asset-cache-v1` 的 `/sp-asset-cache-index.json`；SW 的清理只按这份索引删除，没有索引的旧缓存无法枚举时跳过清理而不是报错。标题页导入按完整 SHA-256 检查预缓存，已有即复用并记入 `/sp-imported-borrowed.json`，所以从任一处导入后，另一处都看得到、在线补齐也不会重复下载。相关记录见 [DEV-20261018-02](development/records/2026-10-18-02-asset-import-fixes.md)。

本地目录与准入的初始实现见 [DEV-20261010-12](development/records/2026-10-10-12-offline-catalog-admission.md)，显式手动更新与完整增量目录见 [DEV-20261011-02](development/records/2026-10-11-02-manual-catalog-update.md)。玩法、模拟、WebSocket 的 v1 布局不因此改变；在线素材预算改为默认不限速，并由服主按需配置。
