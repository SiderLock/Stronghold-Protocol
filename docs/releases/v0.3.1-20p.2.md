# v0.3.1-20p.2：皮肤、连接质量与移动端维护

本版在 `v0.3.1-20p.1` 的 20 人分支基础上，整合皮肤、房间协作、素材加载、网络和渲染维护。游戏完整同步基线仍为上游 **0.3.1**，另选择性采用部分 0.3.2 开发中的改进，不代表完整同步上游 0.3.2。

感谢 [sganggs 和上游贡献者](https://github.com/sganggs/Stronghold-Protocol)提供游戏本体、确定性模拟、插件、基础皮肤与官方特效系统；感谢 [LongQianChen（龙千尘）](https://github.com/LongQianChen/Stronghold-Protocol)提供 20 人容量、固定分组、并行轮选、紧凑协议、预缓存与运维基础。下面按功能说明本版变化，并在对应更新中注明参考思路；冻结引用与采用范围另见[来源与致谢](../REFERENCES.md)。

## 更新日志

### 皮肤选择、动态预览与界面跟随

- **没有战斗模型的图片时装也可穿戴**：商店、干员详情和结算按所属席位显示所选立绘，战斗仍使用可用模型，避免将“可换立绘”误当成已有对应小人。本项采用 **sganggs** 在上游 0.3.2 开发中的[图片时装改进 `77b91081`](https://github.com/sganggs/Stronghold-Protocol/commit/77b91081c7988de7a8fc5304df59fe938f5b5c7c)。多套皮肤、立绘与按 owner 渲染的基础来自 **Flotiarenor** 的 [#685](https://github.com/sganggs/Stronghold-Protocol/pull/685)、[#686](https://github.com/sganggs/Stronghold-Protocol/pull/686)，随上游保留。
- **动态小人预览**：换装界面复用预览画布与模型加载，失败时保留静态图片回退；离开界面和切换对象时释放相应资源。换装与预览交互参考 **alien-zzy** 的 [#652](https://github.com/sganggs/Stronghold-Protocol/pull/652)；该 PR 引用的早期思路来自 **AoyamaT1** 的 [#85](https://github.com/sganggs/Stronghold-Protocol/pull/85)。本分支做了适配，未整套移植其服务端下载安装入口。
- **召唤物随主人换装**：有对应模型与映射时选择相应造型，缺失时回退默认模型。处理思路参考 **FengYuPrime** 的[皮肤与 VFX 手册](https://github.com/FengYuPrime/Stronghold-Protocol/blob/master/docs/FORK-SKIN-VFX.md)。
- **皮肤独立语音槽**：按皮肤选择可用语音，未提供的语音继续走原回退逻辑，参考 **xcdoge** 的 [#734](https://github.com/sganggs/Stronghold-Protocol/pull/734)。
- **穿搭导入导出**：保存和恢复选择配置；导出内容不包含图片、模型、音频或特效文件，也不会替接收者补齐素材。

### 时装特效、模型朝向与动作修复

- **时装特效替换**：读取客户端 CharacterSkinHooker 的替换关系，将已有施法、命中等特效映射到可用的时装资源。替换映射、资源覆盖层和键名规范化参考 **FengYuPrime** 的[手册](https://github.com/FengYuPrime/Stronghold-Protocol/blob/master/docs/FORK-SKIN-VFX.md)，按本项目加载与播放链路重新适配；不代表完整移植其分支，也不代表所有弹道变体均已支持。
- **正背面模型提取**：依据客户端实际 prefab 引用选择 Front / Back，不再只根据文件名猜测；只更新模型时保留其他已有元数据，减少提取结果彼此覆盖。
- **动作元数据修正**：修复宴两套时装及伊芙利特「轻松旅途」的动作信息，并补充缺失动作检查，减少可见模型却播放不到正确动作的情况。
- **魔王技能与挂点**：补齐三技能 AuraHeal 自身、范围和友方特效，以及生命重分配的 burst；统一身体附着点与模型比例，按子层深度处理身体背景，减少错位、大小不符与默认造型遮挡。地面范围和弹道保留原格子尺度。
- 上述能力依赖相应索引与本地资源。**本次便携包不包含新增时装、召唤物模型、时装特效或提取的场景**，具体内容见更新日志后的素材边界。

### 等候房换座与队友重刷申请

- **等候房换座**：可交换空位或 AI 座位；交换真人座位须对方同意，并支持取消、拒绝和申请过期。房主权限跟随本人，不再与第一个席位绑定；进入对局后保持固定席位。
- **保留已有准备与房间规则**：在合法容量调整和换座过程中保留适用的准备状态，开局仍按最终席位建立固定组，不改变各组库存规则。
- **队友可申请重刷**：非房主先发送申请，由房主决定是否发起原有的全员一致投票；申请本身不会直接重刷、暂停倒计时或替队友投票。冷却、过期状态、掉线与身份检查继续生效。
- 重刷申请采用 **zasx77771** 的 [#857](https://github.com/sganggs/Stronghold-Protocol/pull/857) 思路，适配 20 席与全部固定组库存，并补齐插件对局转发和紧急冻结保护。采用的冻结版本与范围见[来源记录](../REFERENCES.md)。

### 连接质量提示与收发积压处理

- **减少慢连接的过时状态积压**：合并相邻、同阶段且可被新状态替代的公共状态，发送前跳过已无必要的编码；阶段变化及其他消息继续保留各自语义。沿用 **LongQianChen** 的紧凑协议、压缩与带宽保护基础，本次增加公共状态合并与诊断，不宣称移植了其他分支的整套增量协议。
- **连续异常才提醒**：将服务器处理 / 发包、页面运行和连接延迟分别提供给提示判断，避免仅凭一次高 RTT、后台标签节流或短暂抖动就认定玩家网络有问题。
- **增加可核对的时间证据**：同时观察 RTT / 抖动、服务器事件循环与处理耗时、发送排队和页面卡顿，帮助后续定位发生在服务端、客户端还是链路。私人诊断记录和原始报告不随包公开。
- **断网与假在线恢复**：连接建立增加超时，网络恢复后检查失效连接；重连时不补发过期操作，减少恢复后突然执行旧请求的情况。
- 这些改动提供测量和缓解手段，**不能倒推历史卡顿一定来自某一方**，也不能消除共享带宽不足。

### 当前素材优先、授权缓存与下载恢复

- **各客户端独立完成当前所需素材**：优先当前页面、简报或战斗真正需要的图片与模型；协议启动图片和模拟预热延后到适用阶段，避免无关资源挡住前台操作。
- **后台补齐需明确授权**：设置与结算页共用控制，默认不擅自开启；各玩家完成自己的当前素材后独立补齐，无需等所有客户端一起完成。前台请求可抢占后台下载，隐藏页面、离线、节省流量及较差连接等情况下暂停或退让。
- **缓存跨局复用**：保留已校验文件，支持关闭和清理；清理不会把使用者导入且仍有效的素材当成普通临时项删除。这里管理的是文件缓存，不等于把全部素材常驻显存。
- **停滞请求释放名额**：服务端将磁盘读取与共享调度循环隔离，客户端和服务端均按“无进度”处理挂起；不把正常但缓慢的大文件简单按固定总时长截断。
- **失败项后置、有限重试**：健康文件继续下载，已经通过校验的进度保留，使用者可以在原页面重试；补充空响应、旧环境与 Service Worker 协作处理，清理或切换版本后不再让迟到任务写回旧状态。

### 移动端、预览与特效资源占用

- **帧率设置**：提供 30 / 60 / 不限帧率并持久保存，限制绘制频率不改变确定性模拟速度。
- **自动分辨率可关闭**：移动端自动调整像素比例有明确设置开关，关闭选择会保存；保留原交互坐标与文字布局，不把低分辨率强制施加给所有使用者。
- **预览生命周期**：不可见预览暂停，切换、关闭和销毁时归还对应引用，减少多个预览互相占用资源或退出后继续运行。
- **图片与 GPU 清理**：限制图片解码并发和缓存预算，及时释放旧场景 GPU 资源与闲置特效纹理；重进相关内容时按需获取。
- **减少重复绘制准备**：复用骨骼矩阵、三角计算与纹理绑定，在保留原绘制顺序的前提下减少重复工作；粒子满额时跳过无效生成，已对魔王追悼二 / 三技能及同类效果做针对性测量，不承诺所有机器获得相同帧率提升。

### 场景准备、计算池与初始化

- **共用场景准备 Worker**：复用准备线程与区域合并结果，切换场景时清理旧资源；不支持相关能力的环境保留回退。此项并非将整个渲染器搬到线程中。
- **预演计算池**：沿用有边界的计算池，补充超时、取消、排队与回退处理，保持候选选择语义，避免请求失效后继续占用计算资源。
- **完整素材摘要增量复用**：文件身份未变时复用已算摘要，文件变化仍重新核对，减少重复读盘；不省略实际变化的校验。
- **初始化描述扫描**：采用 **hesperine** 的 [#823](https://github.com/sganggs/Stronghold-Protocol/pull/823) 正则复用思路，减少重复创建与扫描。该参考已进入上游开发分支，不将其列为本 fork 原创。

## 下载与素材边界

提供自带 Node.js 22.23.3 和生产依赖的四种便携包：**Windows x64、Linux x64、macOS Apple Silicon、macOS Intel**。请选择与系统和处理器匹配的包；运行方式见包根的 `README-开箱即用.md`。校验文件见 `SHA256SUMS.txt`。

**本次不发布独立素材包，也不附带本分支自行提取或新增的游戏素材。** 基础素材只取自作者上游 `v0.3.1` 的原始发布包，并核对该归档的 SHA-256；所有 `public/assets/local/` 和 `data/local*.json` 均排除。新皮肤图片与模型、时装特效、提取的 3D 场景等需要自行准备。缺少可选素材时，相关功能会缺席或沿用默认模型、简化棋盘和原有回退效果，不保证显示本分支演示过的全部画面。

## 升级建议与验证边界

- 建议解压到新目录，先核对本机功能，再按部署文档迁移已有配置。不要直接覆盖运行中的服务器；有正在进行或断线保留的对局时，先等待结束。
- 本版没有附加独立更新包。已有完整安装的素材和本地提取结果不应因升级而自动删除或对外再分发；需要复用时由使用者自行核对来源与兼容性。
- 历史卡顿的具体来源仍需实际线上证据；84 连接共用约 0.8 Mbps 并发下载的压力场景仍未达到原延迟目标，不能宣称已解决所有带宽瓶颈。
- 桌面浏览器的移动视口测量不等于 Android / iPhone 真机或 20 真人长期验收。跨平台包的实际检查范围将在候选核验清单中逐项列出，不把归档检查写成所有平台实机通过。
