# 服主运行配置

**在服务器安装目录执行以下命令**。命令只修改本机私有配置，不需要网页账号或开放管理端口。

## 每房 AI 数量上限

### 计算进程

原版玩法的 AI 布局预演，以及战报过大触发的普通 / 联防整场重算，可在独立子进程中执行，
网络和房间状态仍由主进程管理。默认使用可用 CPU 数减一、最多 2 个子进程；单核默认关闭。
启动前设置 `SP_REHEARSAL_WORKERS=0` 可关闭并恢复原有主线程分片；`1` 到 `4` 可指定进程数。
这是启动配置，修改后须等无对局再重启；不是动态服主命令。

计算池按需启动，AI 房间开局时预热。任务失败、超时或队列满时回退到原分片计算；不截断漏怪、不降低 AI 预演候选数。
测试模式、自定义 Battle 类、虚拟时间工具和玩法插件房间保留原执行路径。默认每个子进程堆上限 512 MiB，
单任务 / 启动超时 30 秒，空闲 60 秒退出，等待队列最多 128 项；过大结果的重算优先于尚未开始的预演。

### AI 席位数量

例如限制每个房间最多 5 名 AI：

```bash
node tools/server-settings.mjs ai-limit 5
```

数值范围为 `0–19`，`0` 禁止添加 AI。房间总席位限制仍正常生效；真人与观战者不计入 AI 数量。

查看当前配置、恢复不额外限制：

```bash
node tools/server-settings.mjs show
node tools/server-settings.mjs ai-limit unlimited
```

- 运行中的服务器约 **1 秒**内应用命令，无需重启。等待室同步显示上限。
- 下调时，等候房从最后一个席位开始自动移除多余 AI，保留真人及前面的 AI；进行中的对局不更改成员，结束回到等候房后再应用新上限。
- 上限限制新增 AI 及开局，不改变房间容量、真人加入、观战或断线续玩。提高上限不会自动补回已移除的 AI。
- 配置保存到 `runtime/server-settings.json`，服务器重启后仍有效。没有配置时默认不限，分发包不包含本机配置。
- CLI 显示的是文件/环境配置，不代表另一个目录下的服务器已读到它；多实例部署必须使用对应实例的配置目录。

## 在线补齐带宽预算

在线素材补齐、冷浏览器获取完整目录和手动更新目录共用一个下载预算。默认总预算与单 IP 预算均为不限，普通游戏 HTTP、WebSocket 和已在进行的对局不排队。服主可以在服务器安装目录动态调整：

```bash
# 总 8 Mbps、单 IP 4 Mbps
node tools/server-settings.mjs asset-cache-limit 8 4

# 恢复默认无限制
node tools/server-settings.mjs asset-cache-limit unlimited unlimited

# 查看
node tools/server-settings.mjs show
```

参数单位是 Mbps，配置会写入 `runtime/server-settings.json`，运行中的服务器约 1 秒内读取。总预算设为 `0` 会关闭在线目录和素材补齐，但不影响本地 ZIP / JSON 导入。启动环境变量 `SP_ASSET_CACHE_TOTAL_BPS` 与 `SP_ASSET_CACHE_CLIENT_BPS` 仍使用字节/秒，仅在没有持久配置时作为默认值。

## 配置目录与启动默认值

服务器与 CLI 都可通过 `SP_SERVER_SETTINGS_DIR` 指定目录。相对路径以安装目录为基准，CLI 的 `--dir` 优先于环境变量：

```bash
node tools/server-settings.mjs ai-limit 5 --dir runtime/server-a
node tools/server-settings.mjs show --json --dir runtime/server-a
```

启动服务器时也应设置 `SP_SERVER_SETTINGS_DIR=runtime/server-a`。可以使用 `SP_MAX_AI_PER_ROOM=5` 指定**启动默认值**，有效持久配置优先于此变量；`unlimited` 表示不限。`SP_REQUIRE_ASSET_CACHE=1`（或 `required`）指定严格预缓存启动默认值，`0`（或 `optional`）允许未完整预缓存。环境变量的修改需要重启，而上述 CLI 命令会动态生效。

请备份私有配置目录，不将其放在 `public` 或提交 Git。首次启动遇到损坏的配置文件会报错；运行中损坏文件会记录警告并继续使用最近有效值。删除配置文件会恢复本次启动时的环境默认值，未设置时恢复 AI 不限、预缓存允许。

配置仍为 version 1；旧文件仅含 `maxAiPerRoom` 时，预缓存要求按 `false` 读取。CLI 修改一个字段保留另一个；同一目录的命令应依次执行，原子替换仍以最后写入为准。损坏文件拒绝部分字段修改，避免更新 AI 上限时误清除严格模式；可备份后修复 JSON，明确保留两个设置。

## 完整预缓存准入

**默认允许未完整预缓存，服主手动开启严格模式。** 在对应服务器安装目录执行：

```bash
# 开启：新创建、加入、最快匹配和观战都需要当前素材完整缓存
node tools/server-settings.mjs asset-cache required

# 关闭限制，恢复默认允许
node tools/server-settings.mjs asset-cache optional

# 核对本机持久配置（包括 AI 上限与预缓存要求）
node tools/server-settings.mjs show --json
```

运行中的服务器约 1 秒内读取。大厅收到新政策；客户端在四种操作前重新核对小摘要、扫描本地实际缓存条目并上报版本、已缓存文件数和字节数。服务器要求这些值与自身当前完整素材摘要一致；只导入目录、素材缺项、旧版本和无报告都返回 `ASSET_CACHE_REQUIRED`。服务器素材有缺项或摘要仍在准备时也拒绝新进入；不会把已拒绝的操作稍后自动执行。

已在房间或对局中的成员保留，当前房间可继续准备与开局；已有玩家和观战者断线后凭原令牌恢复，无需重新满足准入。主动离开后再次进入、换房或从观战转为玩家仍受新准入限制。策略不改变断线续玩期限。

严格模式需要玩家使用支持完整预缓存的 HTTPS / localhost 浏览器。完整 ZIP 或当前目录 JSON 仍推荐由外部渠道分发；没有目录的玩家也可在面板中明确获取完整目录后在线补齐。目录和素材请求共用服主设置的限速与紧急保护；初始化、检查和准入不会自动拉取完整目录。已有完整包包含目录，无需重做大包。使用、导出和更新步骤见 [素材预缓存](ASSET_CACHE.md)。

数量报告用于正常客户端的带宽准入管理：导入时校验素材 SHA-256，进入前重查缓存键；服务器不能凭报告独立证明远端磁盘内容，修改客户端仍能伪造报告。规则与测试见 [D024](development/DECISIONS.md#d024) 和 [DEV-20261010-12](development/records/2026-10-10-12-offline-catalog-admission.md)。

## 房间目录与转让

房间列表是实时内存房间，不是历史记录。所有未离开的真人都掉线时标为「断线保留」并置底，仍计入总房间和进行中统计；房主离线但其他真人在线时只标「房主离线」。进行中的独立模拟默认在最后一次断线后保留 **2 小时**供原玩家续玩；超期后由清理扫描移除身份与房间，普通扫描最长间隔 15 秒。同盟对局仍为 10 分钟，等候房断线席位仍为 60 秒；真正结算后房间回到等候状态，断线席位重新使用 60 秒期限，在线成员可以重开，最后真人离开后释放。已有调用方显式窗口覆盖与带宽紧急保护期间暂缓超期清理的规则保留，见 [D033](development/DECISIONS.md#d033)。

等待室房主可点击在线真人成员卡上的皇冠按钮并确认转让。新房主交换到 P1，其他准备与个人配置保留，旧房主仍需满足普通成员的准备要求。AI、观战和离线成员不能接收转让。对局中不移动座位；因退出发生的自动移交在回到等待室时将当前房主归 P1，避免改变本局固定卡池分组。
