基线 `feat/skin-enhance@ed2ece3a`。本轮覆盖初始化、时装预览、图片解码、特效与移动端画布负载；不改变战斗数值、伤害、结算或素材内容。前一轮场景 Worker 与兼容性工作见 [运行性能排查](RUNTIME_PERFORMANCE.md)。

## 玩家可控制的行为

设置新增 **帧率上限：30 FPS / 60 FPS / 不限**，默认不限以保持旧配置行为；选择保存在本浏览器，立即应用于战场及小人预览。不改变固定步长的战斗计算、游戏速度或结算。实际帧率仍受设备性能与显示刷新率限制。30 FPS 的自动负载判断使用相应帧预算，避免主动限帧触发降分辨率。开发测量页支持 `?fps=30` / `60`，采样跟随实际绘制 ticker。

设置 → 画面质量下方增加 **自动调整渲染分辨率**，默认开启并保存在本浏览器。用户显式关闭后一直保持关闭，刷新不会重新开启。开关立即作用于当前棋盘，不需要重新开局。

仅在触控为主且没有精细指针的设备上，沿用已有连续慢帧负载判断和恢复滞后：负载等级 1 / 2 / 3 将角色及棋盘画布的 DPR 上限降为 1.5 / 1.25 / 1；恢复后逐步升回所选画质。上限始终不超过设备 DPR 与高 / 中 / 低画质的原上限。关闭开关立即恢复所选画质的上限；桌面不受这项分辨率调整影响。

这会在压力较大时降低棋盘与角色的细腻程度；DOM 界面文字、布局、棋盘投影和触控坐标保持原样。不自动关闭特效、不更改用户选择的画质档位。原有移动端「自动」特效使用精简档的行为保留。

## 资源与热路径

后续目录优化：服务端持久化完整素材 SHA，按文件身份与纳秒时间戳增量复用；清单、别名和缺项仍每次构建。Windows 完整库 50,722 文件 / 4,568,422,732 字节首次建立缓存 23.74 秒，随后两次 5.99 / 5.88 秒，均与全量目录逐项相等；两次均复用 50,722 项，摘要计算读取素材字节为 0（清单与图集文本仍需读取）。这不是服务器实测值，也不是首次无缓存启动耗时承诺。

服务器部署前使用候选目录构建器、低 CPU / I/O 优先级扫描同一完整库：首次建立缓存 57.90 秒，随后 5.28 / 5.32 秒，内容与线上目录版本相同。此时没有重启线上服务；该测量不等于整站启动耗时。

骨骼 CPU：仅对当前 Pixi 7 标准槽位变换合并旋转 / 偏斜赋值，再一次更新三角系数；自定义或替换的变换保留原实现。不跳过姿态、动画帧或网格更新。2,000 组旋转 / 偏斜 / 缩放 / 枢轴及后续普通变换操作与原实现数值完全相同，6 套真实模型 126 次像素对比一致。独立浏览器基准使用 478 个真实骨骼矩阵各重复 150 次，预热 3 轮、正反顺序交替 10 轮，中位耗时 18.35→12.85 ms；这是矩阵分解环节，不代表整体 FPS 提升 30%。

| 特效绘制 | 同一绘制 pass 内复用纹理绑定，GPU 新上传后及下个 Pixi pass 重新绑定 | 保留绘制顺序、材质、纹理、粒子数量与混合模式；没有按材质重排透明物体 |
