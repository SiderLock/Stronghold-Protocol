## 需求、范围与验收

用户反馈玩家不知道自己与谁共享卡池，希望将分组作为后续联防和机变改进的基础。本次从局内成员列表开始，用户审阅可切换示意后确认「彩色角标＋同组淡框」。

- 头像左下使用 A–E 彩色组标，同组用同色淡框连接；姓名、LP 和状态继续保持原色，不增设组标题行。
- 使用服务器已公开的固定分组，淘汰、掉线、托管或退出不重分组；单组不显示装饰。
- 保留领袖战绿色搭档框的含义，以及滚动条右侧的单行表情区。
- 只修改局内列表及可复用的分组表现数据，不调整卡池、联防、机变或策略选择的玩法。
- 验证组别映射及缺少元数据的兼容行为；Edge 检查六人、九人、二十人、单组及领袖搭档场景，覆盖滚动与小尺寸布局；检查后关闭测试浏览器并释放测试端口。

已有按功能本地提交授权适用于本次；未授权推送或部署。

## 调查与决定

| 问题 | 证据或来源 | 结论及确定程度 |

| 客户端能否直接取得分组 | `server/match/match/views.js` 的 `poolGroups` 包含固定 `id`、`playerIds`、`scale` | 已确认：不需修改协议或服务端，不能按座位编号除四推算 |
| 新标记的位置 | 用户提供的局内截图、`teamPanel.js` 与 `game.css` | 已确认：头像左下空闲；P 席位、自身标记和 AI 标记保留原角落 |
| 绿色框的含义 | `teamFrameIds` 和当前成员列表 | 已确认：领袖同战场搭档与固定卡池组是不同关系，须并存 |
| 分组是否需要头部行 | 用户接受的示意方案 | 已决定：通过 A–E 和淡框表达，避免增加列表高度 |

| 文件 / 函数 / 操作 | 变化或结果 | 为什么这样做 |
