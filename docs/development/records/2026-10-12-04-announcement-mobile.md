## 需求、范围与验收

用户报告手机 Edge 横屏打开网站时公告过大，下方「下次不再显示」与「关闭」无法点击；补充观察为非全屏时浏览器工具栏进一步压缩可见高度，全屏后可看到关闭按钮。要求修复手机端且不影响电脑端。

范围为普通公告与紧急通知的局部触屏样式、对应开发记录及索引。验收：非全屏高度下公告底部操作始终位于可见区域且能触摸；正文与历史列表仍可独立滚动；电脑端相同环境下的布局几何不变。遵循游戏现有横屏要求，不改变旋转提示或全局 Modal。

## 调查与决定

| 问题 | 证据或来源 | 结论及确定程度 |
|---|---|---|
| 用户设备上的表现 | 用户横屏 Edge 实玩报告，非全屏失败、全屏可关闭 | 用户观察；本机只能进行 Edge 触屏仿真，不能声称已复现该手机的地址栏 |
| 可见高度来源 | `device.js` 已根据 `visualViewport.height` 更新 `--sp-vh`；公告 CSS 仍使用 `vh`，短屏后置规则覆盖为 `94vh` | 源码确认：公告未使用已有可见高度，安全区和外层 padding 的预算也不完整 |
| 底部不能通过滚动找回 | 公告正文独立滚动，footer 为 `flex: none`，页面禁止溢出 | 源码确认：正文滚动不会移动 footer，需约束整个公告容器 |
| 触摸目标 | 公告底部采用 `size="sm"`，通用触屏样式用 44px 伪元素扩张点击区 | 源码确认：需要给局部 footer 实际可见高度，避免操作区伸出屏幕或与邻控件重叠 |
| 浏览器仿真复现 | 修改前 CSS；手机横屏布局高度 280–430px，模拟可见高度 220–320px及安全区 | 已复现布局机制：普通/紧急各五个压缩高度场景越界；例如 844×390、可见高度 300px 时，免提示底边 356.81px、关闭底边 363.59px，超出可见范围 |

用户随后允许适度收窄公告，在两侧保留可点背景，但明确优先保证免提示可勾选。选择只覆盖 `.sp-coarse` 且横屏常见的高度 ≤600px；沿用游戏现有输入特征判断，不引入 UA 判断、`:has()` 或全局弹窗修改。普通鼠标模式保持原布局；短窗口触屏电脑也可能匹配该触屏规则。

## 实现或操作

| 文件 / 函数 / 操作 | 变化或结果 | 为什么这样做 |
|---|---|---|
| `public/css/announcements.css` 的触屏短屏规则 | 仅普通/紧急公告盒在既有 fixed backdrop 内绝对定位；高度使用 `100 × --sp-vh`，扣上下 12px 与安全区 | 不再按可能大于可见区域的 `vh` 居中；可见高度更新即重新布局，不依赖玩家先全屏 |
| 同一规则的宽度 | 限制为 16rem 与可用宽度中的较小值，左右扣留白和安全区、自动居中 | 最小根字号下上限 640px；844px 横屏时左右约 102px 可点击背景，不通过过度收窄挤成多行 footer |
| 底部按钮、免提示标签 | 按钮与标签真实高度至少 44px；按钮伪元素点击区限定于自身 | 保证复选框与关闭都可直接触摸，避免隐藏扩张点击区伸出可见边缘或遮住相邻控件 |
| 历史/详情与标题区 | >900px 的短触屏同样单列切换；标题区最多占正文容器 45%，长标题自身可滚动 | 较宽手机不同时挤入两个面板；最大字号、合法 120 字标题也保留正文阅读区 |

正文和历史列表继续独立滚动，footer 不随之移动。公告发布格式、免提示版本规则、紧急命令、图片和链接安全规则均未改变；未修改其他弹窗、旋转提示、游戏状态机或素材。
